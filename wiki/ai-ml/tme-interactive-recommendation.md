# 从隐式推荐到交互式陪伴：推荐系统的智能跃迁

> 核心主张：推荐产品的下半场，是让推荐系统突破智能上限，从而让用户具备更大的主动权。推荐系统正从「判断你可能喜欢什么」走向「理解你为什么此刻需要什么」；大模型则从推荐链路的**组件**走向**驱动者**，让系统具备推理、交互与自迭代能力。落地上分为三个方向：借鉴大模型技术扩展推荐模型设计空间、引入世界知识与推理突破协同数据瓶颈、由 Agent 驱动推荐链路构建原生交互式推荐系统。

## 背景与问题

### 一个深夜听歌场景

演讲开场展示了一个产品界面：23:23:14，10 月 18 日，深圳，晴 27°C。系统推荐了 a_hisa 的《Town of Windmill（风车小镇）》，并给出这样的解释：

> 周日深夜的深圳，晴天留下的干燥空气还没散，正适合从《Town of Windmill》开始。a_hisa 把节奏放在 63 BPM，钢琴和弦乐先铺起安静的底色，鼓组与贝斯要到副歌才缓缓进入；情绪不是一下子推上来，而是一层层向上走。夜深时听，正合这份不急着抵达的松弛。

用户可以在对话里继续表达「今晚想听纯音乐慢慢铺开，不要人声」，系统再给出「换成带点叙事感的民谣，适合深夜一个人听」「想听点带竹笛音色的轻古风，叙事会香一些」等可点选建议。这个界面同时具备：聊天、陪伴日记、播放列表、对当前歌曲的解释、主动追问与推荐。

### 传统推荐链路做不到的三件事

演讲把「从传统推荐系统走到这里」拆成三个能力缺口：

| 能力 | 要求 | 传统链路的缺口 |
|------|------|---------------|
| 理解音乐内容的内涵 | 不再只识别标签，而是理解 BPM、配器、段落结构，以及这些要素合在一起形成的听感 | 没有从知识来源去理解内容 |
| 解释系统推荐的动机 | 不是完全不可解释的黑盒，而是能说明此刻这首音乐的推荐动机，以及它与用户的联系 | 不具备可交互、可理解的通道 |
| 理解用户输入的含义 | 「来点提神的」不是检索词，而是一种状态描述，需要被翻译成推荐约束 | 没有感知意图的入口 |

演讲的判断是：这三件事在传统推荐链路里很难做到——它既没有从知识来源去理解内容，也不具备可交互、可理解的通道。**推荐产品的下半场，是通过让推荐系统突破智能上限，从而让用户具备更大的主动权。**

### 业界演进的四个阶段

演讲把业界共同走过的路概括为四个阶段，主线是「先把表征能力建强，再让生成成为推荐的基本形式，最终走向可交互的智能体」：

| 阶段 | 做法 | 关键词 |
|------|------|--------|
| 1 强化用户表征 | 把全周期行为压缩成通用的用户表示，一次生产、多处复用，替代各任务各自建模 | 通用表征、跨域迁移、近实时更新 |
| 2 强化物品表征 | 用离散语义码代替纯 ID，使内容的编码方式具备深层语义性，而非只是表层的记忆表征 | Semantic ID、语义对齐、统一表示 |
| 3 生成式统一大模型 | 把推荐重构为指令跟随与序列生成任务，搜索、推荐与用户理解收敛到同一个模型中 | 指令化、统一建模、端到端生成 |
| 4 Agentic 推荐系统 | 推荐能力被封装为可调用的工具，由 Agent 完成规划与编排，系统具备交互、记忆与自我迭代能力 | 工具调用、Context/Memory、自进化 |

贯穿全程的四项支撑能力：

- **Scaling 能力**：dense 参数、sparse 参数 Scaling；
- **内容理解**：基于 LLM/VLM 模型持续深化内容理解；
- **评估体系**：Agentic 的评估与线上巡检能力；
- **推理效率与成本**：训推 + 设计优化，在线上 QPS 下真正可用。

### 两条轴线与「为什么一定会走到 Agent 驱动」

演讲用「两条轴线」概括推荐系统的向外扩展，但该页示意图在 PDF 中为空白（不确定其具体画法）。总结页把这次扩展落成三项要求：

1. 模型要能够接收外部知识；
2. 链路要能够管理知识；
3. 系统要能够与用户交换「暗知识」。

在「为什么一定会走到 Agent 驱动」一页，「燃料的改变」示意区在 PDF 中同样为空白，只保留了结论：对系统的要求逐级传导——推荐系统的模型需要具备接受外部知识的能力，进一步还需要管理知识的能力，所以必须转变为 Agent 驱动。

### 一个常被忽视的事实：推荐系统本身也是个 Agent，但不完备

演讲提出：推荐系统一直在替用户做决策，却没有感知意图的入口、没有跨会话的记忆、也没有解释自己的通道。补齐这三样，纵轴的拓展才真正开始。

## 方案/架构

### 方向一：借鉴大模型技术，扩展推荐模型的设计空间

演讲的前提判断是：推荐领域与大模型领域的许多问题具有对称性，推荐模型的技术迭代应与大模型社区的进展保持同一条时间线。

#### 为什么把 MTP 迁移到推荐

MTP（Multi-Token Prediction）在大模型里解决两个问题，而这两个问题在推荐场景都有对应痛点：

| 在大模型中，MTP 解决什么 | 机制 |
|--------------------------|------|
| 提升模型效果 | 从只预测下一个 token，变为同时预测多个未来 token；在高质量数据见顶的背景下，提高训练信号密度与 token 利用效率 |
| 提升推理效率 | 一次前向预测多个 token，配合投机解码显著减少解码步数；草稿接受率超 85% 时，业界已验证约 1.8 倍加速 |

「在推荐中，它对应什么价值」一栏在 PDF 中为空白（不确定其具体映射）。演讲只给出总判断：推荐模型的设计曾经高度标准化，而大模型带来的技术红利，正让它重新变得有设计空间。

#### 两种 MTP 结构：P-CAR 与 C-CAR

在已全量上线的生成式召回基线之上，分别适配并行与因果两种结构，并针对推荐任务做改造：

| 结构 | 全称 | 关键设计 |
|------|------|---------|
| **P-CAR** | Parallel Controllable Autoregressive Retrieval | 主监督预测 next item，长期监督预测 next second item，共享编码块与 Output Head；两路 Loss 联合训练，推理时可同时取用或只走单一通路 |
| **C-CAR** | Causal Controllable Autoregressive Retrieval | 长期监督接收主干 Hidden Embedding，经 RMSNorm 融合前向滑动的行为序列；对 item token 做掩码，强化模型依赖行为序列完成多步预测 |

架构图显示：P-CAR 的 Primary Supervision Module 与 Long-Term Supervision Module 各自有 Autoregressive Encode Block 与 Output Head，二者共享底层 Autoregressive Shared Module；C-CAR 的长期监督模块通过 RMSNorm 接收主干的 Hidden Embedding，Output Head 与主监督模块共享。

落地范围：QQ 音乐、酷狗音乐、酷我音乐、全民 K 歌、波点音乐、JOOX 的 **10+ 核心点位**带来核心指标收益。相关工作已被 **CIKM 2026 接收为长文**，两种结构的完整设计与消融实验见论文。

> 注：演讲第 11 页的收益图表在 PDF 中为空白，未给出具体指标涨幅（不确定）。

### 方向二：引入世界知识与推理，突破协同数据的智能瓶颈

演讲把「推荐系统作为闭源系统，如何提高智能上限」称为长期被低估的问题。

#### 同一个人群，两种截然不同的答案

对同一细分人群，分别用两种方式得到偏好歌手：

- **基于数值计算偏好歌手**；
- **推荐大模型推理偏好歌手**。

两组结果的 **Jaccard 相似度仅 0.0102**：57 位 vs 42 位，**仅 1 位重合**。两栏的具体歌手名单在 PDF 中为空白（不确定），但该对比说明：世界知识驱动的推理结果与协同数据计算出的结果差异极大，二者不是同一个「偏好」定义。

#### 世界知识补上协同数据的两块短板

| 短板 | 过去 | 现在 |
|------|------|------|
| 没有数据的时候：新用户冷启动 | 依赖热门召回；逻辑预设多、置信度处理主观，结果往往同质化收敛到热门 | 按高熵特征分群，联动推荐大模型直接推理该人群可能感兴趣的歌手与歌曲 |
| 数据量低置信的时候：认知时效性 | —— | 除头部歌手外，推理结果中还出现了一批长尾新生代 |

第二栏「认知时效性」的具体做法在 PDF 中未展开（不确定）。

#### 音乐与视频兴趣的直接因果推理

方法被概括为：**先把资产收敛成语义，再让模型沿语义逐层外推**；同一套框架在不同内容形态下都成立。

一个实例：主题桥接始终清晰，而媒介与形态持续变化。

| 层级 | 例子 | 说明 |
|------|------|------|
| 主兴趣 | 华语摇滚演唱会 | 舞台灯光、乐队编制、字幕与观众互动特征明显，是一条高度集中的兴趣轴 |
| 近邻惊喜 | 英语独立 / 民谣现场 | 语种和曲风变了，但现场音乐的沉浸感保留 |
| 适度惊喜 | 音乐人访谈与创作幕后 | 内容形态已从演出变为访谈，但「音乐」这条主题线索依然可追溯 |

换一类内容，这个能力依然成立：二次元音乐 MV、国产古风战斗、科幻 FPS 实机；K-pop 女团舞台、J-pop 偶像唱跳、音乐节 DJ 电子；猫狗拟人化家庭喜剧、真人肢体喜剧、街头恶作剧互动。演讲的结论是：媒介在变、形态在变，但主题的桥接始终可解释——这类跨媒介关系，过去需要大量行为数据配合精心设计的多跳 trigger。

#### 再进一步：构建推荐垂类大模型

推理结果可以作为特征接入链路，但若要让大模型本身成为推荐模型，需要完整的五个阶段：

| 阶段 | 名称 | 说明 |
|------|------|------|
| 1 | 内容理解（Content Understanding） | 页面未展开具体做法（不确定） |
| 2 | 扩充词表（Semantic ID） | 页面未展开具体做法（不确定） |
| 3 | 继续预训练（Continued Pre-training） | 让新 token 可参与深度推理，而非仅作索引 |
| 4 | 领域 SFT（监督微调） | 统一激活模型在复杂交互场景下的能力 |
| 5 | 强化学习对齐（GRPO） | 多路 reward：格式 / 正反馈与负反馈 / 生态 / 合法性 |

走完这五个阶段，世界知识不再是挂在链路旁边的一路特征，而是成为原生的推荐模型能力。演讲的总结是：**到这里，横轴的拓展就完成了——闭源系统第一次有了来自外部的知识来源。下一步的问题就是如何应用和驱动这些知识。**

### 方向三：由 Agent 驱动推荐链路，构建原生交互式推荐系统

#### 推荐系统具备了交互能力

不再是大模型配合推荐系统，而是**大模型驱动推荐系统**。三个关键构件：

- **推荐能力被封装为 tool**：生成式、语义与可约束推荐成为可被调用的能力；
- **Agent 承担编排职责**：由它决定调用什么、何时调用、如何组合；
- **Memory 跨场景共享**：全场景、全周期、全行为的持续性记忆与主动反思。

#### 决策密度上来了，工程难点也就变了

调用哪个工具、是否追问、何时切歌、用什么口径解释——每一步都是一次决策。演讲列出三类决策：

| 决策类型 | 内容 |
|---------|------|
| 意图与路由决策 | 判断用户想要什么，分发到哪个场景 Agent 与能力模块 |
| 工具调用决策 | 选择调用哪个推荐 tool、传入什么约束、结果如何组合 |
| 素材与播报决策 | 选取新闻与歌曲素材，决定解释的角度、长度与时机 |

页面还并列了一张「领域小模型与通用模型的决策能力对比」表，但表格内容在 PDF 中为空白（不确定其评测项与数值）。演讲只给出结论：

> 交互式推荐的工程难点，往往不在推荐本身，而在于让密集的决策链路足够快、足够稳。这也是为什么通用模型跑得通 demo，却跑不动线上。

#### 交互之后，推荐体验开始丰满

- **持续记忆**：把听歌偏好、交流过的故事与共同经历，延续到下一次相遇；
- **可解释**：结合当下情境、个人记忆、外部话题与音乐内容，解释此刻的推荐。

演讲的判断是：交互式推荐的价值在于具备了更高层次的推荐智能与可解释性，让用户直接感受到陪伴感与可控感，而不再面对一个冰冷的黑盒。

#### 产品形态：真实对话里长出的七类能力

演讲用产品界面截图展示了这套能力在真实对话中的形态：

1. **歌曲背后的故事**：解释某首歌的创作背景与表达（示例提到蔡徐坤《What a Day》与 One-take 现场录制）；
2. **歌手背后的故事**：从歌手首张专辑、合作词人、时代节点讲起（示例提到陈奕迅 1996 年《时代曲》）；
3. **持久化的记忆**：记住用户此前听过的版本与对话（示例提到徐歌阳版《一万次悲伤》）；
4. **相关的音乐资讯**：结合新闻素材做推荐与播报；
5. **对音乐内容的深层理解**：讲 BPM、配器、段落结构与听感；
6. **音乐里的彩蛋**：讲 beat switch、前后半段的反差、合成器音色等细节；
7. **主动推进推荐任务**：在用户没有明确指令时主动追问、切换或推进播放。

界面中还出现「用户希望被…」的偏好标签与向量分数（如 `[-0.013...]`、`[-0.016...]`），说明系统在对话中维护用户偏好表征；其具体含义与使用方式演讲未展开（不确定）。

### 总结：回到那两条轴线

| 要求 | 内容 |
|------|------|
| 01 | 模型要能够接收外部知识 |
| 02 | 链路要能够管理知识 |
| 03 | 系统要能够与用户交换「暗知识」 |

推荐系统正在发生的跃迁：**判断你可能喜欢什么 → 理解你为什么此刻需要什么。**

### 未来展望：第四个方向——持续自我拓展

今天仍由人完成的那部分：Agent 已经在执行推荐，但链路的演进本身——提假设、做实验、看结果、定方向——依然由人驱动。

如果 Agent 能驱动推荐，它能否驱动迭代？演讲给出四步闭环：

**问题诊断 → 方案生成 → 上线验证 → 结果回流**

策略与模型两条管道，共用知识库，实验结果统一回灌。真正的变化在于迭代的主体从「人驱动」转为「系统自驱」——而人的角色，从执行者转为规则制定者与最终审核者。

## 关键工程做法

1. **在已上线的生成式召回基线上做结构改造**：不是从零训练，而是在全量基线之上适配 P-CAR/C-CAR 两种 MTP 结构，降低落地风险。
2. **用「主监督 + 长期监督」共享编码**：P-CAR 共享编码块与 Output Head，两路 Loss 联合训练；推理时可按需取用单通路或双通路，兼顾效果与成本。
3. **用因果结构强化行为序列依赖**：C-CAR 把长期监督接到主干 Hidden Embedding，经 RMSNorm 融合前向滑动序列，并对 item token 做掩码，逼迫模型用行为序列完成多步预测。
4. **冷启动用「高熵特征分群 + 大模型推理」替代热门召回**：先按高熵特征把人群分开，再让推荐大模型直接推理该人群可能感兴趣的歌手与歌曲，避免结果同质化收敛到热门。
5. **跨媒介兴趣用「语义收敛 + 逐层外推」**：先把内容资产收敛成语义，再沿语义从主兴趣推到近邻惊喜、适度惊喜；主题桥接可解释，替代大量行为数据 + 多跳 trigger。
6. **推荐垂类大模型走完整五阶段**：内容理解 → Semantic ID 扩充词表 → CPT → 领域 SFT → GRPO 多路 reward，让世界知识成为原生模型能力，而不是链路旁路特征。
7. **把推荐能力 tool 化，由 Agent 编排**：生成式、语义、可约束推荐都封装成可调用工具；Agent 决定调用时机、参数与组合方式。
8. **用 Memory 打通全场景全周期**：短期/长期记忆与全域历史共享，支撑跨会话的陪伴感与主动反思。
9. **把「快、稳」当成交互式推荐的一等工程指标**：密集决策链路（意图路由、工具调用、素材播报）必须足够快、足够稳，否则只能停在 demo。
10. **用「用户是否主动要求更多端」作为比留存更强的信号**：留存与核心操作指标超预期只是结果，用户自发要求「其他端也有」说明「可以开口要求」已成为推荐的新选择。

## 经验与边界

### 核心经验

- **表征 → 生成 → Agent 是能力递进，不是三个孤立项目**：先有通用用户表征与 Semantic ID，才谈得上生成式统一建模；先有生成式召回与推荐垂类模型，才谈得上 Agent 编排。
- **世界知识补的是协同数据的结构性短板**：冷启动与认知时效性这两个场景，协同数据本身无解；大模型推理提供的是「外部知识来源」，不是替代协同信号。
- **推荐系统本身就是一个不完备的 Agent**：它一直在做决策，缺的是感知意图的入口、跨会话记忆、解释通道；补齐这三样，交互式推荐才成立。
- **「暗知识」是交互式推荐的关键词**：系统不仅要推荐，还要与用户交换那些无法从行为日志中直接读出的偏好、情境与故事。
- **迭代主体可能继续上移**：从人驱动推荐，到 Agent 驱动推荐，再到 Agent 驱动迭代；人的角色转为规则制定者与最终审核者。

### 明确边界与不确定项

- **演示与实际线上系统之间有距离**：演讲多次强调通用模型「跑得通 demo，跑不动线上」，交互式推荐的工程难点在密集决策链路的快与稳；但演讲未给出线上 QPS、延迟、成本的具体数字。
- **世界知识的覆盖与可信度未展开**：推荐垂类大模型的五阶段中，内容理解与 Semantic ID 两阶段页面为空；世界知识的来源、更新机制、事实性校验、版权与合规边界，演讲均未说明。
- **因果推理的「因果」是演讲用词**：演讲展示的是主题桥接与跨媒介外推的案例，未给出因果推断的形式化定义、识别策略或对照实验；将其理解为「基于语义的因果式推理」需谨慎。
- **效果数据披露有限**：除 Jaccard 0.0102 与 1.8 倍加速（后者引自业界）外，MTP 的线上涨幅、交互式推荐的留存/操作指标具体值、领域小模型 vs 通用模型的评测结果均未展示（不确定）。
- **产品指标与用户信号**：「留存及核心操作指标超预期」「用户主动要求更多端」是演讲的定性表述，未给出样本量、统计口径与显著性。
- **组织与业务边界**：演讲者负责腾讯音乐娱乐集团互动视频推荐与创新推荐业务；案例集中在音乐/视频内容，能否迁移到其他推荐场景，演讲未展开。
