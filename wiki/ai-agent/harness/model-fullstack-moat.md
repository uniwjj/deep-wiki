# 模型 + 全栈工程才是护城河

> 核心主张：**对生命的敬畏，必须写进系统的完成条件。** 模型会答，系统要把事办成；榜单第一只是起点，真正的考题是把一项医疗任务完整交付，模型的领先必须兑现为交付的领先。

来源：DACon 2026 北京站主论坛，胡浩源（京东健康 AI 副总裁）《模型 + 全栈工程才是护城河：从医疗 Agent 到全行业启示》。

> 说明：本 PPT 对外版本把绝大多数具体数字脱敏为 `***`，包括评测分数、样本量、任务数、Token 规模与业务指标。本页只记录原文明确保留的指标口径、结构与结论方向，不复原任何被脱敏的数值。

## 背景与问题

### 榜单第一，只是起点

演讲开场先摆出京医千询的专业能力评测成绩，覆盖五类评测：

| 评测 | 说明 |
|------|------|
| 十科正高职称考试 | 同时同地，现场考试 |
| HealthBench Hard 得分 | 具体分数脱敏 |
| HealthBench Total 得分 | 具体分数脱敏 |
| MedBench v*** 榜单得分 | 具体分数脱敏 |
| 自建三维影像评测准确率 | 具体百分比脱敏 |

这些分数在页面上全部以 `***` 呈现，但演讲要表达的不是分数本身，而是下一句：

> **真正的考题，是把一项医疗任务完整交付。**

榜单测的是「模型会不会答」，真实医疗任务考的是「系统能不能把事办成」。两者之间隔着一整套工程。

### 模型会答，系统要把事办成

演讲以「病例资料整理为医生可接手的会诊材料」为例，把任务拆成四个环节，每个环节都有必须核验的对象和典型失败：

| 环节 | 必须核验的对象 | 典型失败 |
|------|----------------|----------|
| 证据 | 原始来源、版本、患者适用条件 | 把未知病情当作已确认 |
| 执行 | 动作参数与工具的真实返回 | 工具失败后仍声称完成 |
| 产物 | 当前文件、图表和正文的一致性 | 分析已更新，正文引用旧数字 |
| 接手 | 依据、未决项和医生的修改记录 | 交出结论，却丢失判断上下文 |

这四类失败分布在证据、执行、产物、接手四个环节，演讲用它们说明：**模型会答，不等于系统把事办成。**

演讲由此给出判断：

> **模型的领先，必须兑现为交付的领先。**

### 长程任务的累积风险

演讲用一个简化算例说明长程任务的累积风险：假设每一步独立成功率为 `***%`，连续 `***` 步且没有恢复机制，整体成功率约为 `***%`（原文写作 `***^{***} ≈ ***%`，具体数值已脱敏）。执行层 Harness 的职责中列有「恢复失败」。

## 方案/架构

### 为完整交付，重构技术栈

演讲给出的技术栈有四层，医学评测贯穿各层：

| 层次 | 系统 | 任务中的职责 |
|------|------|--------------|
| 交付层 | MedWork | 接收目标，支持医生核对和采纳 |
| 执行层 | Harness + Infra | 管理状态，核验执行并恢复失败 |
| 模型层 | 京医千询 / MedCode | 专业理解、任务规划与动作生成 |
| 知识层 | MedWiki | 组织证据，保留版本和适用条件 |

底部还有一条横向机制：

> **医学评测贯穿各层，失败反馈分别进入模型训练与系统改进。**

这四层各自对应一项职责：知识怎么组织、模型怎么分工、执行怎么恢复、结果怎么交接。演讲的「全栈工程」指的就是这四层加上贯穿的评测。

### 知识层 MedWiki：定义知识与条件

MedWiki 把医学知识拆成四个维度：

| 维度 | 内容 |
|------|------|
| 对象 | 疾病、分期、人群、干预、证据 |
| 关系 | 支持、适用、排除、引用 |
| 条目 | 原文、版本、证据等级与位置 |
| 状态 | 已确认、未知、不适用 |

这四个维度对应四类信息：知识在讲什么对象、对象之间是什么关系、每条知识的出处和等级是什么、这条知识当前处于什么状态。「状态」维度区分已确认、未知、不适用三种状态。

### Agentic Search：沿缺口查证

MedWiki 只定义知识与条件，真正查证靠 Agentic Search。演讲列出四项能力：

- **语义匹配结合医学实体与条件约束**：把医学实体和适用条件一起纳入匹配
- **追查支持、反驳及版本依赖**：不只找支持证据，也找反驳证据和版本依赖
- **按证据覆盖与未决冲突分配搜索深度**：证据覆盖不足或存在冲突时继续深挖
- **缺证据继续查，缺事实请人补充**：把「查不到」和「事实缺失」分开处理

演讲的总结是：

> 用 Agentic Search，把相关性检索推进到**证据闭环**。

### 执行层 Harness：把算力变成做事能力

演讲给 Harness 定义了四项能力：

| 能力 | 内容 |
|------|------|
| 持续状态 | 保留目标、进度、未决项与当前产物 |
| 统一工具契约 | 训练、推理和评测复用环境，核对真实返回 |
| 模型与上下文 | Model Mesh 统一供给，按任务装配知识、记忆与状态 |
| 高频决策下沉 | 主模型聚焦规划和验收，局部操作交由快速模型 |

演讲把 Harness 的定位概括为「把算力变成做事能力」。

页面底部还有三个规模指标（技能数、线上业务数、分类任务单次对照提速），具体数值均已脱敏。

### 模型层分工：MedCode 与 med-jev

模型层分两层：

| 模型 | 职责 |
|------|------|
| MedCode | 专业理解、任务规划与最终验收 |
| med-jev | 高频、局部操作；各业务方法由 Skill 组织 |

MedCode 承担「专业理解、任务规划与最终验收」，med-jev 承担「高频、局部操作」，具体业务方法由 Skill 组织。这与 Harness 的「高频决策下沉」一致：主模型聚焦规划和验收，局部操作交由快速模型。

### 交付层 MedWork：接收目标与支持接手

MedWork 是交付层，职责是「接收目标，支持医生核对和采纳」。

这与第 4 页的「接手」环节对应：交付要求医生能依据材料接手，并保留自己的判断。

## 关键工程做法

### 把指南写成程序，把条件变成检查

MedCode 的核心做法是「把指南写成程序，把条件变成检查」，病例事实与医学规则分别表示。演讲把它拆成四步：

| 步骤 | 动作 | 要求 |
|------|------|------|
| 1 | 抽取类型化事实 | 保留未知项 |
| 2 | 核对适用条件 | 绑定指南原文 |
| 3 | 执行规则与动作 | 读取真实返回 |
| 4 | 输出限定动作与依据 | 交医生复核 |

演讲用联合 TNM 静态评测展示效果，对比三种设置下的同一模型：

| 设置 | 结果 |
|------|------|
| 无指南 | `***%` |
| 提示词指南 | `***%` |
| MEDCODE | `***%` |

评测集是 LungCURE-EN 原发布的 `***` 个病例，评分标准是 **T、N、M 全对才计分**。具体分数已脱敏；MEDCODE 一栏在页面上用红色标出，无法从脱敏后的页面判断实际排序。

演讲同时给出边界：

> 规则可以测试和回归。**事实抽取与规则编写仍可能出错。**

### 医学评测：先定义什么叫做对

演讲把评测放在「北极星」的位置：

> **先定义什么叫做对，才知道算力该投向哪里。**

评测体系由京东健康与上海人工智能实验室共建，包含三类：

| 评测 | 检查什么 | 数据与范围 |
|------|----------|------------|
| MedEviBench | 证据溯源、安全质控与逻辑表达 | MedBench v*** 专项赛道 |
| MedRealMM | 真实多模态问诊 | `***` 条样本、`***` 科室、`***` 个模型 |
| 三维影像评测 | 完整 CT / MRI 的证据与判断 | 真实放射报告与三维影像 |

评测流程是「医生逐例修订并批准 Rubric，自动 Judge 按标准评价」。

演讲还列了临床共建的三组合作（具体数量已脱敏）：

- 广附一呼吸团队：`***` 余选择题与 `***` 道 Rubric 问答
- 北肿沈琳团队：`***` 道病例决策题
- 重附一周新雨团队：`***` 项临床导向系统评价

> 能力筛选与消融 / 训练范围收敛 / 精准蒸馏 / RL 能力与时延对齐 / 灰度验证

### 长程任务：为一份可验收的成果

演讲以一个长程论文写作任务为例，展示「可验收成果」怎么定义。任务分五个阶段：

> 选题与搜索 / 证据与分析 / 图表与文件 / 渲染与布局 / 成稿与修订

方法配置由 `***` 个定制化文件、`***` 个预设 Python 脚本、`***` 篇子任务说明文档组成（数值脱敏）。

交付门控有三条：

- **内容完整**：数据与图表相互对应
- **路径可用**：交付文件真实生成
- **编译成功**：渲染与布局检查通过

> **每一项都通过，任务才算完成。**

页面还给出长程执行规模（自主循环步数、工具调用步数、上下文 Token 数），具体数值均已脱敏。

### 系统改进：下一次进步不必等下一轮训练

演讲把改进对象拆成三类：

| 对象 | 怎样改变 | 验收对象 |
|------|----------|----------|
| 模型参数 θ | SFT、RL 与教师分布监督 | 模型与通用能力回归 |
| 本次状态 x | 按真实返回更新进度与产物 | 当前任务的一致性与完成条件 |
| 外部方法 S | 更新 Skill、规则与工具 | 候选版本回归与专业验收 |

三类对象的验收对象不同。演讲的判断是：

> 让每一次真实失败，推动下一次系统改进。专家定位问题，人机共同分流；改进 Rubric、Skill 或 Harness，验收后复用。

「验收后复用」对应四步循环的最后一步：只让通过验收的方法进入下一次任务。

### 影像任务：专家怎样取证，模型就怎样学

演讲以一个影像任务为例，展示如何记录专家的操作与判断轨迹。专家轨迹包括：

- 选择序列，三视图观察
- 分割 / ROI，调窗
- 提交答案，审阅并修正轨迹

对应的工具契约是：

| 项 | 内容 |
|----|------|
| 工具 | `pick_image` |
| 输入 | `series_index` |
| 返回 | 模态、期相与形状 |

### 交接：把接管权交给医生，把过程留在系统

演讲用「把接管权交给医生，把过程留在系统」概括医疗协作的边界。交接必须保留三类信息：

| 类别 | 内容 |
|------|------|
| 证据 | 出处、版本与适用条件 |
| 过程 | 实际操作与真实返回 |
| 未决项 | 缺失资料与尚未确认的前提 |

第 4 页「接手」环节要求保留「依据、未决项和医生的修改记录」，与本页三类信息相呼应。交接要求保留这三类信息，让医生可以核对、修改、采纳。

## 经验与边界

### 模型可以买，验收过的方法买不到

演讲最后把全行业启示压缩成一句话：

> **模型可以买，验收过的方法买不到。**

支撑这句话的是一个四步循环：

| 步骤 | 内容 |
|------|------|
| 观察 | 记录真实任务轨迹、工具返回与专家反馈 |
| 改进 | 训练模型，或修改 Prompt、Skill、规则与工具 |
| 验收 | 在同类任务比较版本，完成业务回归与必要专业人审 |
| 复用 | 只让通过验收的方法进入下一次任务 |

演讲对算力的判断是：**算力既增强模型，也改进整个执行系统。**

### 「对生命的敬畏」的工程含义

结尾页把这句话展开成三个问题：

- 业务对象和适用条件怎样表示？
- 动作与真实返回怎样接起来？
- 谁来接手，按什么标准验收？

这三个问题是演讲对「把敬畏写进完成条件」的具体展开。

最后一句是：

> 把能力交给医生，把更多时间留给患者。

### 边界

- 这是**单厂商、单领域**的实践分享，四层技术栈、评测体系和训练方法都来自京东健康的医疗场景；演讲标题虽为「到全行业启示」，但原文没有给出跨行业落地数据。
- PPT 对外版本**所有关键数字均已脱敏**，包括评测分数、样本量、任务数、Token 规模、业务指标。本页不复原、不推算这些数值。
- 部分效果原文称「项目阶段观察」（如广医一呼吸项目），未说明是否随机对照，也未给出统计显著性、样本量或评测周期。
- 「模型没换，交付提升」是内部对照实验的结论，原文给出了任务规模口径（`***` 道科研任务）与固定 GPT Judge 的设置，但没有给出 Judge 与人工评分的一致性数据。
- 演讲把「全栈工程」定义为四层技术栈 + 贯穿的医学评测，原文没有声称这是行业通用分层。
