# 从数据工程到知识工程：通俗导读

> **一句话：数据工程解决"数从哪来、怎么算"；知识工程解决"这个数是什么意思、该信哪个版本、凭什么信"。**
>
> 本页是 [[data-to-knowledge-engineering]]（详细记录页）的白话版读法：同一份 30 页幻灯片，换一条更容易走通的阅读路径。详细的概念地图逐类拆解、七维对比表、案例完整数据与边界，仍以详细页为准。

## 0. 为什么这份 PPT 容易读不进去

- **四种文体拼在一起**：第 1 章是本体论概念（类图、公理），第 2 章是行业全景（五家厂商路线），第 3 章是案例与方法，第 4 章是自家产品。前后没有过渡句。
- **术语没铺垫**：TBox / ABox、语义视图、本体、Trace 直接上，第一次看会断线。
- **真正的结论在最后一页**：前 29 页在铺垫，第 30 页才给出"五个观点"。
- **最实用的两页被夹在中间**：第 16 页（知识从哪来）和第 22 页（评估是门禁），很容易翻过去。

所以别按顺序读，按下面这条因果链读。

## 1. 主线：一条因果链

1. 企业把数据整好了——表、指标、看板都有。
2. 但 Agent 用起来还是错。**错在口径，不在数据。**
3. 口径不在表里：文档里常有三四个互相冲突的版本，最全的那份在人脑子里。
4. 所以别要求人写文档，让人正常工作，把"纠正"记录成 **Trace**。
5. Trace 是原料，不是知识。要经过**抽取 → 绑定 → 裁决 → 校验 → 发布**才是知识。
6. 发布之后业务还在变，所以要**评估当门禁、增量更新**。
7. 这条链路就是知识工程——本质是"非结构化 → 结构化"，所以数据工程的管线、分层、增量、评估全部能复用。

## 2. 四个概念，用大白话过一遍

第 4 页那张"概念地图"是全场最抽象的一页，其实只说了五句话（幻灯片称"公理"）：

| 幻灯片的说法 | 人话 |
|---|---|
| 关系表是一种信息 | 表只给事实，不给含义：`o_sts_cd=3` 是几，你不知道 |
| 语义视图 = 绑定到关系表的本体 | 把"指标、维度、口径、过滤条件"贴到表上，成为表的说明书 |
| 知识图谱 = 含实例的本体 | 有概念也有具体对象（这张订单、这个客户） |
| 关系表 + 语义视图 推出 知识 | **光有表没有口径 = 不能用；光有口径不落表 = 空谈** |
| 数据形态互斥且完备：结构化 / 非结构化 | 世界就这两半，所以非结构化那半必须靠抽取 |

类比（本页的说明性比喻，不是原文表述）：数据是食材，信息是切好的菜，**知识是菜谱加火候**。语义视图就是把菜谱钉在每道菜上——谁来做都不会跑偏。

常见术语的一句话对照：

| 术语 | 一句话 |
|---|---|
| 本体 Ontology | 概念 + 关系 + 规则 |
| TBox / ABox | 概念层 / 实例层（"有客户这个概念" vs "客户张三"） |
| 语义视图 Semantic View | 一组指标定义，查询时编译成 SQL |
| Trace | 人和 AI 的交互记录：提问、纠正、确认 |
| 知识图谱 | 本体 + 实例 |
| EDD | 拿评测当开发流程，而不是上线前跑一次测试 |

## 3. 为什么难：原料不在文档里

第 16 页那张"三层供给"是全场最有共鸣的一页：

| 难度 | 在哪 | 怎么拿 |
|---|---|---|
| 容易 | 文档、Wiki、制度、SOP | 蒸馏（案例二） |
| 中等 | SQL、Dashboard、代码、配置 | 从使用痕迹归纳（案例一、Genie 路线） |
| **最难** | **人的口径、经验、判断、习惯性流程** | **只能靠 Trace** |

演讲的判断很直接：**最难的知识，人自己都没意识到该写出来**。所以别指望"让大家写文档"，而是让人正常工作，系统把"不对，GMV 不该含退款"这句话 trace 下来 → 生成候选规则 → 人工确认 → 评测 → 语义版本 +1。

它有一句金句：**第二次数据革命的原料是 Log（人的行为），第三次数据革命的原料是 Trace（人的认知）。**

Trace 里常见的五类线索：指标口径纠偏（"GMV 不应该包含退款"）、时间口径纠偏（"按支付时间，不是创建时间"）、过滤条件补充（"要排除测试商家"）、同义词补充（"成交额就是 GMV"）、关联关系补充（"订单表按 store_id 关联门店表"）。

## 4. 五条路线：不是选最强，是选起点

第 2 章容易被看成"五个产品广告"，其实它在说：**本体没有统一标准**（建什么 / 怎么运行 / 如何裁决 / 怎样持续维护，没有任何一套标准同时规定），所以这五家各自选了不同的"保证"和"自由"。

| 路线 | 它保证什么 | 它放弃什么 | 什么时候用 |
|---|---|---|---|
| Palantir Ontology | 能查还能改（Action 写回），治理闭环 | 开放、轻量、便宜 | 高治理的运营闭环，**不是起点** |
| Semantic View 家族 | 口径唯一、查询时编译成 SQL、结果准 | 只管结构化分析，不能行动 | **大多数企业的起点** |
| Apache Ossie | 开放、不锁定、跨工具交换 | 没有运行时，本体层刚起步 | 想避免被厂商锁死 |
| Databricks Genie | 覆盖面广、自动生成、越用越多 | **排序不等于验证** | 补长尾上下文 |
| Agent Memory | 灵活、零建模、个体记忆 | 无校验、无裁决 | 个人偏好，**不能当组织真值** |

一句话记法：**从左到右，用"保证"换"自由"**。所以正确问法不是"哪个最好"，而是"我这个场景愿意为哪种保证付多少建模成本"。逐条拆解与七维对比见 [[ontology-five-routes]]。

## 5. 两个案例：它们在证明同一件事

**案例一（第 17 页）**：拿企业里现成的"业务问题 + SQL"反推语义视图。模型只把 SQL 当文本读、不执行；每条结论带证据编号，证据不足就留空待人工确认。结果：F1 = 1.0、精确率 97–100%、覆盖 ×2.3。但演讲自己给了天花板：**理论上限 50.8%**——SQL 里没出现过的关系永远蒸不出来。所以它既证明"自动化可行"，也证明"单靠存量痕迹不够，要和 Trace、文档互补"。

**案例二（第 19 页）**：某头部内容平台文档整理得很好，RAG 却不好用。原因不是知识少，是**知识太多**：同一个指标三四种写法散在 25 篇文档里，召回一堆相似口径，Agent 分不清。解法是把文档再蒸馏一层成结构化语义视图——指标口径正确率 38.1 → 73.4，选表 F1 80.3 → 85.7，token 成本 −52%，长尾耗时 p90 −21%，294 次越界生成零编造（内部评估、保守下限）。

最反直觉的一句：**数据来源没增加，反而变少了**（SV 上下文 3.3k token < 召回的 3.9k token）。结论是——**不是喂更多上下文，而是把上下文压成唯一口径。**

## 6. 四条工程共识：这才是可落地的部分

1. **开发期让 Agent 探索，生产期跑确定性管线**（Agents in Dev, Artifacts in Prod）。演讲者自己试过"把决策权交给模型自主循环"，结论是**全部负效**。生产期模型只做抽取，流程由编译好的 DAG 决定。
2. **知识管线 = 数据管线的奖牌架构**（Bronze / Silver / Gold）。知识工程本质是"非结构化 → 结构化"，所以分层、增量、评估、回滚都能照抄数据工程。
3. **评估是门禁，更新是常态**。三件套：金标题库（正题 + 负题）、证据校验器（引用的表列必须有据）、质量证书（PASS 才发布）。这就是从 TDD 到 EDD，见 [[edd-evaluation-driven-development]]。
4. **Eco-loop**：使用 → Trace → 蒸馏 → 评估 → 认证入库 → 服务 → 回到使用。越用越准，也解释了为什么知识平台不是一次性交付，见 [[knowledge-eco-loop]]。

## 7. 第四章可以快进

第 25–29 页是云器自己的产品（AI Lakehouse V1→V2、SingSight / AI-ETL / 知识工程、CoALA 三层模型、三种服务模式）。有价值的信息只有一条：**三个模块正好对应 Eco-loop 的三段**（SingSight = Trace + 评估，AI-ETL = 蒸馏，知识 = 入库 + 服务）。其余是厂商自述，看的时候打个折。

## 8. 只记五句话

1. 表不等于知识，**表 + 口径才是知识**。
2. 最贵的知识在人脑子里，**只能从 Trace 里捞**。
3. 五条路线是五种"保证 vs 自由"的取舍，**先选起点，别选最强**。
4. 知识要靠**绑定、裁决、校验、发布**四步加工，LLM 抽取只是第一步。
5. **评估是门禁**：没有金标和证据校验，宁可不上线。

## 9. 对做平台的人，四件可落地的事

1. **先做语义视图，别先建本体**：挑一个高频指标，把口径、维度、过滤条件、证据来源写清楚。
2. **把 Trace 接上**：把用户纠正转成候选规则，人工确认后版本化。
3. **建三件套门禁**：金标题库（正负双套）、证据校验器、质量证书。
4. **按数据管线做知识管线**：分层、内容哈希增量、版本与回滚。

## 10. 重看路线（约 15 分钟）

只看这些页就够：**4（概念地图）→ 5（五种表达形态）→ 13 / 14（五条路线对比）→ 16（三层供给 + Trace）→ 17 / 19（两个案例）→ 20 / 22 / 23（三条共识 + 闭环）→ 30（五个观点）**。

第 7–12 页是五条路线的逐个介绍，可以当字典查；第 25–29 页是产品，可跳。
