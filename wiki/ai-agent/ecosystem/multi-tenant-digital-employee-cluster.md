# 从工作流到智能体集群：企业级多租户数字员工的工程化落地

> 核心主张：企业 Agent 的范式要从“无状态工作流自动化”升级为“可记忆、可管控、可协同、可进化的数字员工自治体系”。演讲把工程底座视为规模化的核心——租户隔离、权限、安全、多角色协同、统一管控（Token / Skill / 记忆 / CoT / 对话审计 / 性能）——而不是单点 Demo。“把数字员工真正「工程化」，它才能从演示 Demo 变成生产力。”

## 背景与问题

### 讲者与团队

何碧宏，群核科技 SRE 团队负责人、软件开发专家、稳定性委员会核心成员。2020 年加入群核科技，曾担任监控、可观测及应用团队负责人，主导公司根因分析、故障自愈、故障演练、AIOps 及 SRE 数字员工等 SRE 平台建设；此前在诺基亚工作十余年，参与诺基亚 DevOps 平台及网管系统的架构与建设。

### AI 在群核 SRE 团队的四阶段演进

| 阶段 | 时间 | 做法 | 结果与问题 |
|------|------|------|-----------|
| 1. 机器学习 | 2025 年前 | 流量预测、指标异常检测、日志分类、根因分析等有限场景；门槛较高，与算法团队合作 | 场景有限 |
| 2. AI 工作流 | 2025 年 | 跟随大模型发展（GPT / DeepSeek / 千问）；用 FastGPT、Dify 构建典型 AI 工作流；落地 SRE 小助手、告警智能处理、日志/调用链/指标 AI 分析、工单/故障/告警/告警风暴根因分析、变更分析等 | AI 低门槛化，SRE 大量场景应用，但维护繁琐 |
| 3. OpenClaw & Hermes | 2026 年初 | OpenClaw 和 Hermes 流行时第一时间探索；基于 K8s Pod + 公司 DevOps 平台，构建员工可自由部署云端 OpenClaw/Hermes 实例、自建数字员工的系统 | 100+ 人创建实例并用于小助手问答、文档处理；初级数字员工，智能大幅提升 |
| 4. 自研数字员工 | 2026 年 5 月 | 爆发安全、权限、资源浪费（Pod 占资源大、低频实例闲置）、统一管控、系统集成等问题；开始自研数字员工系统 | 成熟数字员工，走向可控、精准、高效 |

演进主线：机器学习 → AI 工作流 → OpenClaw & Hermes → 自研数字员工。

### AI 工作流的四个瓶颈

| 瓶颈 | 原文描述 |
|------|---------|
| 01 灵活性不足，修改困难 | 静态 DAG 写死流程，新情况须改图重画、适配传参分支，非常麻烦 |
| 02 无记忆沉淀 | 无状态执行，业务经验无法沉淀复用 |
| 03 多角色协同难 | 多智能体协作靠人工串联，无法自组织 |
| 04 租户与权限弱 | 隔离与精细鉴权弱，生产治理不足 |

演讲的结论是：“图越画越乱、一次性资产不可复用——AI 工作流适合固定流程自动化，撑不住复杂长链路业务。”

### 为什么自研：直接部署 OpenClaw & Hermes 的四个问题

1. **权限与安全**：缺乏统一权限底座，SSO / 工具调用 / 数据访问无法精细管控；版本更新频繁、早期版本漏洞多、无法统一升级，用户使用无统一管理有未知风险。
2. **资源浪费**：Pod 占用资源大，使用频率低、用几次就闲置的实例浪费大量资源。
3. **管控混乱**：Token / 记忆 / 对话审计无法统一治理；Skill 管理升级、版本管理升级很混乱。
4. **门槛与集成**：非技术人员门槛高、遇问题无法解决；难以深度集成公司内部系统与业务。

选型依据：既充分拥抱开源生态、快速复用业界成熟能力，又能深度融入公司内部生态，对接内部系统、适配业务规则、顺滑嵌入企业现有团队协作流程。

## 方案/架构

### 云端多租户数字员工集群：五层整体架构

| 层 | 组成 |
|----|------|
| 用户访问层 | 企信 / 飞书、Web、AI 客户端、API/SDK |
| 接入管理层 | Gateway（认证与对话路由）、数字员工管理 |
| 运行层 | Hermes 集群 ↔ LLM 服务（旁侧依赖） |
| 能力服务层 | Skill Hub、远程知识库、本地 llm-wiki、Hindsight 远端记忆 |
| 基础设施层 | Kubernetes、持久化存储、COS 备份 |

整体设计原则：以开源 Hermes Agent 为核心，构建云端多租户数字员工系统，既复用开源成熟能力，又充分融入企业内部业务和流程。

### 多租户隔离：K8s 容器 + Hermes 多 Profile

隔离架构自下而上分三层：

1. **K8s 容器承载海量员工**：Ingress/Service 按路由规则把客户端请求分发到不同 Hermes Pod；每个 Pod 包含 Hermes 容器、用户路由网关、Profile 管理。
2. **Hermes 多 Profile 逻辑隔离**：每个 Profile 是独立数字员工的逻辑运行单元；租户 A 的 Profile A1/A2 与租户 B 的 Profile B1/B2 分属不同逻辑域；持久化卷 PVC 下按 `/profiles/A1`、`/profiles/A2` 分目录。
3. **数据 / 会话 / 记忆三层隔离**：租户间数据、会话、记忆严格隔离；通过 Profile 用户级环境变量隔离，实现多用户独立访问——每个用户拥有独立的环境变量空间，互不干扰、独立配置。

关键设计点：**用户与租户是不同维度**。同一个 Profile（如 Profile A1）下，用户 A 和用户 B 各自拥有独立的环境变量、个人访问凭据、独立执行上下文；分别使用 A/B 凭据访问外部业务系统中各自授权的数据。

### 知识架构：远程知识库 + 本地 llm-wiki + Hindsight 记忆

| 组成 | 内容 | 作用 |
|------|------|------|
| 远程知识源 | 企业知识库（规章制度、产品资料、技术文档等）；业务知识库（业务流程、领域知识、行业资料等） | 接入企业存量知识与知识图谱 |
| 本地知识源 | 本地 llm-wiki（本地知识文档、历史经验、案例沉淀） | 沉淀专属与团队知识 |
| 本地会话与工作记忆 | 会话上下文、临时信息、工作记忆；位于 Profile 持久化目录 | 支撑当前会话与任务执行 |
| 远端记忆服务 Hindsight | 记忆写入（记录重要信息与经验）、记忆检索（查找相关记忆）、记忆回忆（在对话中唤醒过往记忆） | 跨会话长期记忆 |

数据流：远程知识源与本地 llm-wiki 通过“知识检索”汇入 Hermes 数字员工；Hermes 与 Hindsight 之间是双向“记忆读写”；本地会话与工作记忆跟随 Profile 持久化目录。

### Skill 架构：数字员工的“手脚”

Skill Hub 的流程是：集中注册（统一纳管 Skill）→ 版本管理（版本测试与演进）→ 审核与分发（发布到各 Profile）→ 统一版本分发。

Hermes 数字员工 Profile 负责任务编排与 Skill 调用，Skill 覆盖日志、指标、调用链、变更、拓扑等类别；工具形态包括 CLI、API、MCP、脚本、命令行、业务工具。每个 Skill 调用都经过“权限/范围校验”，约束条件是“当前用户凭据 + 资源白名单 + 命令白名单”；右侧监控与审计记录调用记录、执行结果、异常与耗时、用户与资源追溯。Skill 最终访问的外部资源与数据包括日志数据、指标数据、调用链数据、变更数据、拓扑数据、企业数据中心。

### 存储与备份：Profile 独立本地存储 + COS 备份

- **日常备份**：每个数字员工（Profile）的数据独立存储在本地，包含配置、会话、本地记忆、本地知识库、Skill 清单及版本；运行中的 Hermes Pod 为 Profile A/B 生成 ZIP 备份包，定期上传到 Tencent Cloud COS（按 `profile-A/时间戳`、`profile-B/时间戳` 组织）。
- **灾难恢复**：从 COS 选择某个 Profile 备份 → 下载 ZIP 备份包 → 恢复到持久化目录 → 新 Hermes Pod 恢复 Profile 和 Skill 版本 → 更新路由映射 → 重新提供服务。
- **数字员工复制**：可以把一个数字员工的数据直接复制到另一个，实现快速克隆。
- 注：远端知识库与 Hindsight 数据由对应服务单独备份。架构图中的备份时间戳（如 2024-10-01）是示例。

### 五种落地形态

| 形态 | 做法 | 实例 |
|------|------|------|
| 1. 问答小助手 | 数字员工以“对话问答”形态嵌入日常工作，用户直接提问、获取答案与建议；门槛最低、覆盖最广 | 监控问答小助手、DevOps 小助手、算力平台 KHCP 智能助手 |
| 2. 内部系统嵌入 | 把问答能力直接嵌入公司内部系统，用户就地唤起 AI 分析，无需下载或跳转 | 日志 AI 分析、调用链 AI 分析、告警 AI 分析、告警风暴 AI 分析、前端崩溃 AI 诊断、发布变更分析 |
| 3. 人与数字员工协同 | 数字员工先分析、自动处理；需要人工判断时，人进入同一对话，相互补充信息，共同完成处理任务 | 告警智能处理 |
| 4. 多数字员工协同 | 多个数字员工分工协作，通过流程 + 状态机编排，各自承担专属职责，共同完成复杂长链路治理任务 | 稳定性任务 AI 自动化治理平台 |
| 5. IM 融合 | 对接企业微信智能机器人实现单聊；数字员工成为群里的正式成员，可直接 @ 问答，24 小时在线 | 企业微信、企业微信群 |

## 关键工程做法

### 1. Skill 治理：核心是“边界与互斥”

演讲把 Skill 治理的核心定义为：厘清每个 Skill 的能力边界与互斥规则——谁负责哪件事、每个 Skill 的功能和边界都提前定义好，从根源杜绝“Skill 泛滥、重复造轮子”。原话强调：不仅仅“统一注册”，而是要更进一步做“边界划分 + 互斥约束 + 官方调优”。

配套五条治理手段：

1. **统一认证规范**：指定 Skill 规范，包括权限、安全、版本、兼容本地 / SaaS 双模式使用，统一注册认证。
2. **推荐认证 Skill**：推荐官方认证、官方调优的 Skill，用户优先选用。
3. **统一版本升级**：实现 Skill 版本管理，一处升级全域生效，杜绝版本混乱。
4. **收敛去重**：同一能力只留认证版本。
5. **对 Skill 进行评测**：接入监控，评测性能、正确率，调优工具调用、思维链、匹配的知识库。

示意图中，日志 Skill、调用链 Skill、告警 Skill、变更 Skill、拓扑 Skill 分别对接日志数据接口、调用链数据接口、告警数据接口、变更数据接口、拓扑数据接口，底层统一要求“边界清晰、职责互斥、官方调优”。

### 2. CoT 治理：把“想太久”收敛成可复用路径

治理前，一个真实问题的思考过程可能超过 16 分钟，消耗大量 token；治理后收敛到 2 分钟以内。演讲给出一个完整案例：问题是“IT 运维组近 30 天的稳定性如何”。

| 指标 | 优化前 | 优化后 | 变化 |
|------|--------|--------|------|
| 耗时 | 16 分 14 秒 | 1 分 44 秒 | 性能提升 80%+ |
| 总 Token | 649,926 | 174,436 | Token 节省 70%+ |
| 输入 Token | 635,106 | 171,342 | — |
| 输出 Token | 14,820 | 3,094 | — |

CoT 治理四件事：

1. **标准化思维链**：基于具体任务，统一规范推理路径，约束大模型按预设骨架思考，而非天马行空自由探索。
2. **剔除冗余思考**：去掉无效试错与重复推理，并发代替串行（比如工具调用），让思考路径收敛、更短更直接。
3. **最优路径、覆盖典型、特殊案例、脚本代替重复推理和计算**：基于历史经验，针对问题总结最优路径，覆盖大多数典型和长尾的少量特殊案例；用生成固定脚本代码代替重复执行的推理和计算。
4. **统一维护可评测、可审计**：数字员工 CoT 集中管理、版本可追溯，效果可评测，问题可定位、可优化，持续迭代。

优化前后的链路差异：

- **优化前**：分析稳定性维度 → 寻找合适 Skill → 反复推理与工具选择（查故障、查工单、查告警、查变更异常，每一步都要“思考下一步”）→ 大量原始数据上下文 → 原始数据传入大模型 → 大模型分析并生成报告。特征是“串行等待、反复思考、大量原始数据上下文”。
- **优化后**：指定 Skill 执行 → 并行查询（故障、工单、告警、变更异常）→ 结果保存本地 → 固定脚本分析 → 仅把分析结果传入大模型 → 大模型生成报告。特征是“并行执行、本地分析、仅传入分析结果”。

### 3. 持续进化飞轮：记忆 + 知识 + 技能协同

飞轮的循环是：业务运行 → 经验沉淀 → 知识迭代 → 能力增强 → 协同进化 → 闭环反馈 → 回到业务运行。支撑它的四件事：

1. **核心能力分层**：数字员工 / Skill / 知识库 / 长效记忆各司其职。
2. **可管控记忆**：规则化记忆约束输出，保障一致性。
3. **CoT + 记忆联动**：长效记忆 + 思维链，输出稳定可追溯。
4. **多源知识**：专属 / 业务 / 企业存量 + 知识图谱。

### 4. 六层性能治理：从链路到记忆

| 层 | 治理动作 |
|----|---------|
| 01 链路 / CoT | 大模型常尝试无法执行的步骤（如访问某些 web 页面），造成失败白耗时；通过 CoT 指定规避，缩短思考链路 |
| 02 Skill | 监控 Skill 耗时与错误，针对性治理调用失败、调用超时的 Skill |
| 03 大模型 | 监控大模型调用耗时，定位调用慢，替换性能差的模型 |
| 04 知识库 | 为各数字员工建专项知识库，提高命中率、减少检索耗时与错配 |
| 05 上下文 | 多轮对话上下文易膨胀，精简上下文、控制长度，降低推理耗时与 Token |
| 06 记忆 | 优化长效记忆检索命中，减少重复检索，快速定位相关知识 |

演讲同时给出边界判断：六层协同治理可显著缓解性能问题，但性能是持续的行业难题，仍是未来迭代第一优先级。

### 5. 多数字员工协同：流程 + 状态机，而不是“流程调度”

稳定性任务 AI 自动化治理平台的编排如下：

- 稳定性异常信息（工单、告警、错误日志、应用异常、变更分析异常、SLA 指标异常）进入后，由“异常聚类识别数字员工”“根因分析数字员工”处理，形成稳定性事件。
- 稳定性事件分三条路径：
  1. **故障**：应急数字员工发起应急 → 应急协同 → 应急完成 → 复盘数字员工复盘 → 预案、经验沉淀。
  2. **专项治理任务**：拉群治理 → 持续分析 → 跟进状态 → 治理完成 → 经验沉淀。
  3. **无需治理事件**：自动处理。
- 另有“稳定性专项治理进度跟进数字员工”“错误日志等专项修复数字员工”等角色。

关键机制：**AI 数字员工和工程师都是独立 Worker，基于 Issue 当前状态和数据，自主领取符合条件的工作，而不是由流程调度**；状态流转驱动任务交接，故障处置 → 修复 → 提交自动化，最终形成稳定性任务的全流程闭环治理。

### 6. 平台侧的统一治理能力

- 云端多租户低资源占用：海量员工低资源、可复用；一个 Pod 支持多员工共享、自动均衡，低频使用资源占用少。
- 统一管控与治理：Token 消费 / Skill / 记忆 / CoT / 对话审计 / 权限安全 / 数据安全 / 性能优化。
- SSO 权限集成：对接公司 SSO 等权限系统，精细权限管理。
- 友好管理页面：数字员工 / 用户 / 对话管理 + 使用情况监控。
- 友好对话体验：流式输出、多文件上传、文件图片预览、生成文件下载。
- 企信深度融合：企信机器人 / 群聊 / 企信小助手。
- 快速创建员工：1 分钟创建、一人可建多个；模板一键创建相似能力的数字员工。
- 可进化：记忆 + 知识 + 技能协同，越用越聪明。
- 多场景自由应用：问答 / 个人 / 团队 / 运维助手、数据分析、内部系统嵌入。

## 经验与边界

### 三个实践经验总结

1. **能力沉淀，构建自进化飞轮**：构建记忆、知识、技能三层协同机制，实现业务经验持续沉淀、迭代复用。
2. **企业级落地，工程底座是核心**：租户隔离、权限、安全、多角色协同，是企业 Agent 规模化落地的必备底座能力。
3. **多数字员工协作：基于流程 + 状态机编排**：治理无序智能体交互，实现权责清晰、状态可交接、业务闭环。

### 四个未来迭代方向

1. **深耕性能优化**：降低推理耗时，突破毫秒级响应瓶颈，精简链路，提升实时业务体验。
2. **优化 CoT 精细化推理**：进一步强化思考链路，提升模型输出准确率与业务稳定性。
3. **迭代知识库治理体系**：优化知识精准召回，缓解知识错配、遗忘、漂移问题。
4. **完善多智能体协同框架**：补齐标准化协同、全链路闭环管控能力，支撑大规模数字员工集群。

### 边界与不确定项

- **模型与推理栈未展开**：架构图只把“LLM 服务”画成 Hermes 集群的旁侧依赖，未说明具体模型、路由策略、推理框架或多模型切换方案。
- **“多租户”与“多用户”是两个维度**：租户由 Hermes Pod + Profile 隔离，用户由 Profile 内的用户级环境变量与凭据隔离；原文没有展开 Profile 的创建、配额、跨租户迁移等管理细节。
