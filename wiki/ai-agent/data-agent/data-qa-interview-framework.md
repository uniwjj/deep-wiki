# 智能问数面试框架：语义层作为类型系统

一篇面试向的整理。它的第一句就定了口径：**问数面试不是考 Prompt 写得花不花，而是证明你懂类型系统、权限、对账、幻觉分类**。本页把文章的骨架抽出来，作为设计与答问时的检查清单。

## 六条考察线与各自的证明点

| 考察线 | 典型问法 | 你要证明什么 |
|--------|---------|-------------|
| 分流 | 问数和 RAG 怎么分？ | 结构化走 SQL，文档走检索 |
| Schema Linking | 模型怎么知道用哪张表？ | 只链已登记指标/维度 |
| 幻觉 | Text2SQL 为什么会编？ | 错指标/错粒度/不可加/越权，分开治 |
| Trust | 用户怎么知道这数能信？ | 路由 + SQL 校验 + 结果对账 |
| 权限 | 行级权限放哪？ | 执行前过滤，不靠 Prompt |
| 评测 | 问数成功率怎么报？ | 覆盖率、路由、对账，不吹 100% |

## 七步答题框架

1. **澄清**：指标问数、文档问答，还是预测？
2. **结论**：先路由；指标必须走语义层。
3. **画链路**：意图 → 语义绑定 → 校验 → SQL → 对账 → 展示。
4. **说原理**：Schema Linking 是有限类型匹配，不是搜全库。
5. **说 trade-off**：覆盖不足就拒绝/澄清，不要硬编。
6. **说生产**：权限、审计日志、口径版本、Eval 集。
7. **补一个坑**：SUM 毛利率 / 用下单当 GMV。

文章给的「万能开场」直接可用：

> 我先确认问题类型。GMV、趋势走语义层生成受控 SQL；制度文档走 RAG。LLM 只做意图和 Schema Linking，不定义口径，也不直接扫明细。上线看三件事：路由对不对、SQL 过不过校验、结果能不能和预计算指标对上。成功率是目标加评测，不承诺百分之百。

## 术语：标准说法与常见误区

| 术语 | 标准说法 | 常见误区 |
|------|---------|---------|
| 智能问数 | 自然语言到受控分析查询 | 等于 ChatGPT 查库 |
| Text2SQL | 在语义约束下生成 SQL | 等于随意 JOIN 任意表 |
| Schema Linking | 把问法绑到已登记指标/维度 | 等于向量搜表名 |
| 语义层 | 指标、维度、关系、权限、展示名 | Prompt 或一张宽表 |
| Trust | 可解释的可信度（路由/SQL/结果） | 等于模型置信分 |
| 覆盖率 | 问法能命中语义资产的比例 | 等于准确率 |
| 澄清/拒绝 | 覆盖不足时问用户或拒答 | 等于产品失败 |
| 幻觉 | 生成了语义层不允许的结构 | 等于用户不满意 |

## 意图路由：先判类型再选路径

三条路径，各有自己的执行栈：

| 问题类型 | 路径 |
|---------|------|
| 指标 / 趋势 / GMV | 语义层（指标定义、维度管理、口径统一）→ 受控 SQL（安全可控、权限收敛、防随意查询）→ OLAP 或湖 Gold 层 |
| 制度 / 文档 | RAG：湖上 chunk → 向量 + 元数据 → 向量检索、元数据过滤、混合排序 |
| 预测 / 排序 | Feature Store（特征管理、复用、一致性）→ 模型（预测输出、排序打分、决策支持） |

两条要点：

- **只有 RAG 是减分**——「一个 RAG 打天下」是典型减分回答。
- **混合问题是 SQL 取数 + 可选文档解释**：「为什么 GMV 跌了」先取数，再按需检索文档解释。

## Schema Linking：把语义层当类型系统

五步链路：**识别业务术语 → 解析语义类型 → 建立类型约束 → 验证 JOIN 规则 → 生成 SQL**。中间有一步「安全边界」：只允许链到语义 catalog 里已注册的度量/维度/关联。

四类约束（图里列的白名单、粒度、可加性、权限）：

- **白名单**：只允许授权模型、只支持既定范围；
- **粒度**：必须限定时间/空间，只支持可按粒度计算；
- **可加性**：只支持可加计算、只支持可按维度加；
- **权限**：RBAC + 行级控制，执行前过滤。

错例与正例的对照很清楚：**直接扫描 50 张 bronze 表、随意 JOIN** → 幻觉 JOIN（不存在或不兼容）→ 错误结果/性能崩盘/安全风险；**只用语义 catalog** → 类型安全、语义一致、正确可审计。

两句可直接背的判据：

> 模型是消费者，不是口径定义者。

> 口径 Owner 是业务/指标负责人，不是表 Owner。口径不清，口径 Owner 背锅。

## Trust 三层：SQL 跑通了也要问「这个数凭什么信」

| 层 | 校验什么 |
|----|---------|
| 1 路由 | 分类正确率：问数 / RAG / 拒绝 |
| 2 SQL | 执行前：指标命中、粒度、可加性、行级权限 |
| 3 结果 | 对账：与预计算对账（如 GMV）、口径版本脚注 |

公式与指标：

```
成功率 = 覆盖率 × 路由正确率 × 对账通过率      （不承诺 100%）
```

配套监控指标：覆盖率、澄清率、对账通过率、采纳率。真实边界是文章那句「问数成功率 = 语义覆盖 + 路由正确 + 对账通过」，**不是「模型越大越准」**。

## 幻觉四类：分开治，才谈得上评测

| 类型 | 典型例子 | 架构拦截 |
|------|---------|---------|
| 错指标 | 用下单金额当 GMV | 展示名 → 指标 ID 白名单；声明语义与口径，非白名单指标拒绝 |
| 错粒度 | 订单行 SUM 成订单头 | 语义层声明 grain；查询粒度与指标不符则拦截，提示正确粒度 |
| 不可加 | 直接 SUM 毛利率 | additive 标记；不可加指标阻断聚合，强制使用正确算法/改写分子分母 |
| 越权 | 查出别人的数据 | 执行前 ACL：行/列/字段级，越权直接拒绝 |

治理动作也是分类型的：错指标→澄清同义词口径、业务确认实际量级；错粒度→必限 grain、加 GROUP BY、维度保持一致、订单头去重；不可加→重写分子分母、加权平均、避免直接 SUM（例：利润/GMV）；越权→执行前 ACL、鉴权验证 Token、脱敏数据水印、仅看本域数据。

> 别只说「模型乱编」——评测要按类型拆。

## 十道高频题（标准答法 + 减分回答）

| # | 题目 | 参考答法要点 |
|---|------|-------------|
| Q1 | 智能问数和 RAG 怎么分流？（美团/携程） | 数值、趋势、同比走语义层 SQL；制度、流程、非结构化走 RAG；「为什么跌了」先 SQL 再可选 RAG。**减分**：ChatBI 就是让 LLM 查全库 |
| Q2 | 为什么必须有语义层？宽表不够吗？（字节/阿里） | 宽表解决加速，不解决同义指标、可加性、权限下推、口径版本；Schema Linking 需要有限、稳定的类型系统；宽表可当物化，不能当契约 |
| Q3 | Schema Linking 怎么做才不像搜表？（字节/阿里） | 问法先归一到指标/维度 ID（同义词表 + 可选向量只做候选召回），再按语义层 Join 图生成 SQL；禁止把 200 张 Bronze 表塞进 Prompt。追问「召回错了怎么办」→ 置信低则澄清（「你说的 GMV 是支付成功还是下单？」） |
| Q4 | 用户说「用户数」怎么选指标？（数仓交叉） | 「用户数」是口头词不是指标，应澄清 UV / 注册用户 / 活跃用户；语义层为每个指标配别名与示例问法，冲突必须澄清 |
| Q5 | Text2SQL 幻觉有哪些类型？如何分别治理？（阿里） | 见上文四类；治理在架构（白名单、粒度、可加性、ACL），评测集按类型分开统计，不要只报一个「准确率」 |
| Q6 | 行级权限放 Prompt 行不行？（安全） | 不行。权限在语义层定义，执行前写入 SQL 谓词或视图；生成后再让模型「不要泄露」不可靠；审计日志记录谁问了什么、命中哪些指标 |
| Q7 | 覆盖不到的问题怎么处理？（产品×架构） | 拒绝或澄清优于胡编；把 miss 日志入湖驱动指标字典补全；覆盖率是运营指标，不是上线当天的 100% |
| Q8 | 问数效果怎么评？和数据湖什么关系？（评测） | 按层评（见下节）；query、生成 SQL、命中指标 ID、对账结果回流入湖形成 Eval 集。**减分**：「我们看用户点赞」 |
| Q9 | 多轮「再按城市拆」怎么保持语义？（高阶） | 会话状态保存已绑定的指标、时间、过滤；追加维度必须仍在该指标允许维度内；越界（把订单粒度指标拆到点击）应拒绝；不要每轮从零猜全库 |
| Q10 | 设计企业问数，湖和语义层在哪？（架构师综合） | 问法 → 路由：文档 → RAG（湖上 chunk + 向量索引）；指标 → 语义层（口径/维度/权限）→ 受控 SQL → OLAP 或湖 Gold。日志/Eval/对账回湖。主动说：覆盖不足就澄清、Trust 三层展示给用户、模型不拥有口径 |

## 按层评测

| 层 | 指标 |
|----|------|
| 路由 | 问数 / RAG / 拒绝 分类正确率 |
| Linking | 指标 / 维度命中率 |
| SQL | 可执行率、校验拦截率 |
| 结果 | 与预计算对账、人工抽检 |
| 产品 | 采纳率、二次追问率 |

## 二面/三面开放题

| 问题 | 期望答案 |
|------|---------|
| 问数把毛利率 SUM 了，产品要不要显示数字？ | 拦截或改写，并解释不可加 |
| 业务说「先上线再补字典」？ | 最小可用语义包（核心 20 指标）才能上，否则幻觉不可控 |
| 同一问题两个口径版本？ | 绑定生效日/版本，回答里露出口径脚注 |
| Agent 能否自由写 SQL？ | 只能调受控 Tool（如 `query_metrics`），评 tool call accuracy |
| 用户满意度高但对数对不上？ | 满意度 ≠ 正确，要以对账为底线 |
