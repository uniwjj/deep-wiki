# Data Agent 交付阶段四支柱

> 出自 [[data-agent-delivery-methodology|Data Agent 项目落地方法论]] 第 05 章。交付阶段解决的命题是**验收问题——做得对不对**，终点是数据化标准逐条达成、双方确认验收。

**四支柱是接力不是并列**：沟通标准化把验收标准定下来 → 自动化构建场景把标准变成问题集 → 自动化测案例把问题集跑成数值 → 标准化排错守住数值的稳定。

## 支柱一：沟通标准化

项目事故一半以上发生在"没对齐"——需求、口径、承诺、验收。解法是把"和人打交道"变成有模板、有清单、有留痕的标准动作，即三个标准化：

1. **标准话术挖掘场景**：场景价值挖掘标准化——价值问卷调研、访谈话术模板；同一套问题挖出客户真实场景与价值点，不靠临场发挥。
2. **标准问题列表 → 验收标准**：场景核心问题列表定数量（如 20+ 条）；准确性目标定数值（如命中率 ≥ 90%）；验收标准 = 问题列表 + 数值目标，**启动即写死**。
3. **标准流程推进项目**：推进模式启动即定——站会怎么开、过什么内容、节奏如何；口径对齐、验收确认延续同一套模板与留痕。

**验收标准**：对接记录可追溯；换人对接，问出的信息一致。

## 支柱二：自动化构建场景

自动化只投在"规模化、重复、高成本"的动作上——场景构建的自动化 = 基于问题列表快速技术选型 + 开放产品接口批量构建，其余不折腾。

1. **问题列表 → 快速技术选型**：问数产品两大技术路线——**宽表问数（NL2SQL）/ 指标问数（指标语义）**；基于问题列表自动判断选型（问题模式 → 技术路线）；现状判断：大型企业指标问数仍是主流。
2. **产品开放核心接口，AI 批量创建**：产品提供 CLI 能力，核心工作接口可编程调用——如 AI 快速批量创建指标，替代人工逐条配置；规模化动作自动化，人效提升显著。
3. **自动化的边界**：只有大规模指标构建类场景值得自动化；其余初始化成本不高，不做过度自动化。
4. **业务助手发布规范**：准备多个业务助手——测试 / 基线 / 生产分层管理；依次审核后上线（测试通过 → 基线确认 → 生产发布），保障生产业务助手的稳定性。

**验收标准**：技术选型由问题列表驱动、有据可查；批量创建类动作由 AI 完成；生产业务助手经测试 / 基线审核后发布。

## 支柱三：自动化测案例

测试是 Data Agent 项目极为耗时的环节——原文举例：100 条问题跑批，第 98 条出问题，改一条提示词，全部问题重跑一遍。循环测试的耗时是隐性黑洞，自动化是唯一的解。

1. **问题列表录入 + 校对规则**：问题列表全量录入测试集（来自沟通标准化的核心问题列表）；首次设置校对规则，核心 = 比对 SQL 生成规则 + 思维链判断准确性。
2. **循环跑批，产出三个关键值**：
   - **准确性值**：全量问题的对错比率
   - **稳定性值**：多次跑批结果的一致程度
   - **收敛值**：多轮迭代后问题逐步收敛的趋势
3. **自动化回归，消除循环耗时**：任何变更（提示词 / 知识 / 语义）→ 自动全量重跑；知数类 agent 产品已提供自动化测试能力，直接启用。

**验收标准**：准确性 / 稳定性 / 收敛值持续记录；**问题列表即验收报告**——用数据说服甲方，比任何表述都有力。

## 支柱四：标准化排错

Data Agent 属于市场新品，产品自身问题与数据问题排查都极度耗时——排错效率决定交付人效的天花板。解法 = **排错 Skill 化：机器先排，人只处理机器排不了的**。

1. **问题分类 + 固定排查路径**：问题分类——检索 / 口径 / 规则 / 幻觉，分类定路径；每类问题固定排查 SOP，不临场发挥。
2. **排错 Skill 化：售后业务助手承载**：在售后业务助手上配置一系列排查问题的 Skill；形成"提问 → 澄清 → 规则检索 → 兜底 → 沉淀"的排错工作流；降低排错难度、提升排错效率。（原文附内部文档《售后业务助手解决方案》链接：https://p.pages-hub.netease.im/p/c13b44fcb62546af92b9f7 ）
3. **留痕沉淀 + 根因提报**：排错留痕——现象 → 根因 → 解法 → 防复发，回流知识库；根因提报——同类问题聚类后一次提报，解决一类。

**验收标准**：同类问题重复出现率下降；排错记录全部可查；售后业务助手承担标准排错入口。
