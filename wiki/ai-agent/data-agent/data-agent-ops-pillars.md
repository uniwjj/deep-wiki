# Data Agent 运营阶段三支柱

> 出自 [[data-agent-delivery-methodology|Data Agent 项目落地方法论]] 第 06 章。运营阶段解决的命题是**价值持续性问题——价值能不能持续**；验收通过不是终点，价值持续才是终点。三支柱保障价值生长。

## 支柱一：价值监测

验收通过后，标准不能丢——交付阶段的量化指标继续在运营阶段被监测，价值是否持续由数据说话，不靠感觉。

1. **后台数据 → 可视化看板**：运营看板呈现活跃度、使用率、命中率、反馈数；了解用户行为——谁在用、怎么用、用得多不多。
2. **看活跃度，定位具体问题**：活跃变化即价值信号，下滑即预警；下钻到具体问题——未命中、低置信度、反馈集中的问题逐条定位。
3. **持续优化业务助手性能**：看板发现的问题反哺知识、语义、规则；优化闭环——看板发现问题 → 定位 → 优化 → 回归验证 → 看板确认。

**验收标准**：价值指标有持续记录；下滑有归因、有处置、有闭环；看板问题反哺助手性能提升。

## 支柱二：用户赋能

场景会变化，未来场景需要客户有能力创造。用户赋能 = 方法论全程参与 + 使用者培训与调研 + 工作经验 SOP 化——让客户从使用者变成创造者。

1. **方法论全程参与**：让客户全程参与交付方法论——用户学会场景交付方法论；理解运营持续的重要性——价值持续性靠运营，不是上线即结束。
2. **使用者赋能：培训 + 满意度调研**：组织 AI 培训，让业务助手使用者会用、用好、有兴趣；使用满意度调研——体验数据化，驱动持续改进。
3. **Skill 培训：工作经验 SOP 化**：让每个业务人员把自己的工作经验 SOP 化；业务人员从使用者变成沉淀者与创造者。

**验收标准**：客户能独立维护知识与提出新场景；满意度有持续调研记录；业务人员 SOP 沉淀量持续上升。

## 支柱三：以点扩面

一个场景的价值是点，业务面的价值是面。以点扩面 = 组织扩散 + 场景收集机制 + 产品能力反哺——让企业的业务助手场景矩阵越来越丰富，也让团队的角色从交付一个场景变成可持续陪跑。

1. **扩散路径：小部门 → 多部门 → 多分公司**：从小部门起步，验证后向多部门、多分公司持续扩散；每扩一层，复用已验证的标准、知识资产与用例库，成本递减。
2. **场景收集机制：大赛 + 培训分享**：以大赛方式收集场景——鼓励全员参与，挖掘新场景、推动立项；通过培训分享等方式持续发现场景机会，鼓励大家落地。
3. **产品能力反哺，场景矩阵丰富化**：新场景持续反哺产品能力，产品随使用不断进化；企业的业务助手场景矩阵越来越丰富。
4. **角色定位：从立项场景到可持续陪跑**：不只是一个立项场景的一次性交付，而是一个场景变成可持续陪跑——持续参与、持续运营、持续扩展。

**验收标准**：扩散路径清晰（小部门 → 多部门 → 多分公司）；大赛 / 培训持续产出新场景立项；场景矩阵数量持续增长；客户关系走向可持续陪跑。
