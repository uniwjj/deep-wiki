# 词元与有效词元

> **一句话定位**：Agent 干了活，价值怎么算？第 12 章的回答是——用词元算。词元是智能体的计量、定价、交易、结算单位；但**没有本体，词元就只是一个数字**，本体用实体/属性/关系/行动四层语义锚点把数字变成服务，再用"有效词元"把未被使用或未达服务等级的词元挡在商业计量之外。本章的总命题是"**本体定义世界，词元驱动未来**"（第 12 章 / PDF 第 205–217 页）。

## 1 词元：智能体服务的价值单元

### 1.1 根本问题：Agent 干了活，价值怎么算？

原文设定背景："2026 年，智能体开始大规模进入生产环境。但一个根本问题始终没有解决：Agent 干了活，价值怎么算？"（12.1.1 / PDF 第 205 页）

三组原文例子（数字原样保留）：

| Agent | 做了什么 |
|-------|---------|
| 设备 Agent | 监测了 **1000 台**设备，发现 **50 次**异常，触发 **20 次**维护行动 |
| 质量 Agent | 检测了 **5000 件**产品，识别出 **30 件**缺陷，追溯了 **5 个**问题批次 |
| 供应链 Agent | 优化了 **200 个**订单的排产，调整 **30 次**物流路径，降低 **15%** 的库存 |

每一组后面紧跟一句"这些服务值多少钱？"，原文的答案是：**在传统模式下，Agent 的价值无法计量。**

传统三种收费模式及其问题（PDF 第 205 页）：

| 模式 | 做法 | 原文指出的问题 |
|------|------|--------------|
| 模式一：项目制 | Agent 作为项目的一部分交付，价值包含在项目总价中 | "至于 Agent 本身值多少钱，说不清楚" |
| 模式二：订阅制 | 按月收费，不管用多用少，价格固定 | "Agent 用得少，客户觉得亏；Agent 用得多，供应商觉得亏" |
| 模式三：免费 | 作为平台功能的一部分，不单独收费 | 价值包含在平台服务中，无法单独计量 |

三种模式的共同问题是三条"没有被"：价值**没有被精确计量**、**没有被合理定价**、**没有被有效交易**。

### 1.2 政策指向

> 2026 年 7 月，国家数据局副局长**余英**在**2026 中国国际大数据产业博览会**上表示，鼓励基于词元应用的商业模式创新，探索词元交易等新型交易模式，深化词元应用与工业、医疗、金融等领域的深度融合，推动形成"**数据飞轮**"效应。（12.1.2 / PDF 第 205 页）

原文随后给出判断："词元（Token），正在成为智能体服务的价值单元。"

### 1.3 词元的四重单位属性

（12.1.2 / PDF 第 205–206 页）

| 单位属性 | 原文论证 |
|---------|---------|
| **计量单位** | 每一次 Agent 调用都消耗词元。数据访问消耗词元，模型推理消耗词元，工具调用消耗词元，Agent 协同消耗词元 |
| **定价单位** | 每一次 Agent 调用都可以通过词元定价。不同 Agent、不同服务、不同场景，词元价格可以不同 |
| **交易单位** | 客户购买词元，Agent 消耗词元，供应商获得收益 |
| **结算单位** | 词元结算记录不可篡改，支持审计追溯 |

效果（原文三联句）：让智能体服务从"无法计量"走向"**精确计量**"，从"无法定价"走向"**合理定价**"，从"无法交易"走向"**有效交易**"。

### 1.4 词元经济的四个核心环节

（12.1.3 / PDF 第 206 页）原文收尾句是："这四个环节，都需要本体的支撑。"

| 环节 | 环节要回答的问题（原文） |
|------|----------------------|
| 第一环：**词元登记** | 词元 ID 是什么？词元类型是什么？词元来源是什么？词元权属是谁？词元有效期是多长？ |
| 第二环：**词元计量** | Agent 调用消耗了多少词元？数据访问消耗了多少词元？模型推理消耗了多少词元？ |
| 第三环：**词元定价** | 词元的价格由什么决定？是成本加成，还是市场供需，还是质量分级？ |
| 第四环：**词元交易与结算** | 谁买词元？谁卖词元？交易价格是多少？结算周期是多长？ |

## 2 本体是词元的语义锚点

### 2.1 没有本体，词元就只是一个数字

（12.2.1 / PDF 第 206–207 页）

原文先给出一个三调用场景：设备 Agent 调用一次数据访问服务，消耗 **1000** 个词元；质量 Agent 调用一次模型推理服务，消耗 **2000** 个词元；供应链 Agent 调用一次工具调用服务，消耗 **1500** 个词元。然后追问：这 1000、2000、1500 个词元，到底代表什么？

原文给出的回答链条是：

- **没有本体**：1000 个词元可能代表一次设备数据查询，也可能代表一次设备数据分析，还可能代表一次设备数据导出——"没有语义，词元就没有意义"。
- **有了本体**，词元就有了语义含义：

| Agent | 调用的服务 | 本体锚点 | 词元代表的业务含义 | 词元数 |
|-------|-----------|---------|------------------|--------|
| 设备 Agent | 数据访问服务 | `Equipment` 实体 + `equipmentStatus` 属性 | 查询设备状态 | 1000 |
| 质量 Agent | 模型推理服务 | `QualityInspection` 模型 + `defectDetection` 任务 | 执行质量缺陷检测 | 2000 |
| 供应链 Agent | 工具调用服务 | `ProductionScheduling` 工具 + `optimizeSchedule` 方法 | 执行生产排程优化 | 1500 |

结论："本体为词元提供了语义锚点。它让词元从'一个数字'变成'一项服务'。"

### 2.2 四层语义锚点体系（必看页 207–208）

12.2.2 用一句话定义：**本体为词元提供四个层次的语义锚点。**

必看页 207 的"**词元语义锚点体系**"金字塔图，副标题为"本体为词元提供四个层次的语义锚点，让词元从'数字'变成'服务'"。自塔尖至塔底依次为：**行动锚点 → 关系锚点 → 属性锚点 → 实体锚点**（实体锚点位于蓝色塔基层，含数据实体、模型实体、工具实体、Agent 实体四个图标）。

| 层 | 图中定义 | 图中示例 | 原文内容 | 原文举例 |
|----|---------|---------|---------|---------|
| 第一层：**实体锚点** | 定义核心实体及其唯一标识 | 数据实体 / 模型实体 / 工具实体 / Agent 实体 | 数据访问词元关联数据实体，模型推理词元关联模型实体，工具调用词元关联工具实体，Agent 协同词元关联 Agent 实体 | 诊断 Agent 调用的模型推理服务关联到 `EquipmentFailureDiagnosis` 模型实体；该实体有明确类型、能诊断哪些故障、诊断准确率、适用设备 |
| 第二层：**属性锚点** | 定义实体的属性特征和状态信息 | `equipmentStatus` / `temperature` | 查询设备状态的词元 → `equipmentStatus`；查询设备温度 → `temperature`；查询设备振动值 → `vibration` | 设备监测 Agent 调用的数据访问服务关联 `equipmentStatus`；该属性为**枚举类型**，取值包括**运行中、停机、故障、维修中、待机**，含义是设备的当前运行状态 |
| 第三层：**关系锚点** | 定义实体之间的关系和约束 | `belongsToLine` / `canReplace` | 查询设备所属产线 → `belongsToLine`；查询设备可替代设备 → `canReplace`；查询设备影响产线 → `affectsProductionLine` | 决策 Agent 调用的工具调用服务关联 `canReplace`；该关系**定义域是 Equipment，值域是 Equipment**，含义是"一个设备可以替代另一个设备" |
| 第四层：**行动锚点** | 定义可执行的动作和操作指令 | `switchEquipment` / `adjustOrder` | 执行设备切换 → `switchEquipment`；执行订单调整 → `adjustOrder`；执行质量返工 → `reworkQuality` | 执行 Agent 调用的工具调用服务关联 `switchEquipment`；**前置条件**：源设备故障、目标设备可用、目标设备能力匹配；**参数**：源设备编号、目标设备编号、切换原因；**后置影响**：源设备状态更新、目标设备状态更新、产线产能更新、订单交付风险更新 |

原文小结："四层锚点，让词元从数字变成语义。"（12.2.2 / PDF 第 208 页）

同一张图右侧还有一个"**语义锚点应用**"面板，把五个词元核心业务动作映射到语义锚点上（图中小字，逐项照录）：

| 业务动作 | 图中说明 |
|---------|---------|
| 词元登记 | 基于语义锚点明确词元含义与边界 |
| 词元计量 | 基于语义锚点进行精确计量与统计 |
| 词元定价 | 基于语义锚点评估价值与制定价格 |
| 词元交易 | 基于语义锚点匹配供需与完成交易 |
| 词元结算 | 基于语义锚点进行清算与价值分配 |

图底部的"核心价值"条："通过四层语义锚点体系，为词元构建完整的语义网络，实现从数字标识到智能服务的价值跃迁。"

### 2.3 语义锚点的三个作用

（12.2.3 / PDF 第 208–209 页）

| 作用 | 原文表述 | 原文例子 |
|------|---------|---------|
| 作用一：让词元**可理解** | 客户购买词元时知道这个词元代表什么服务 | 不是"1000 个词元"，而是"1000 次设备状态查询"；不是"2000 个词元"，而是"2000 次设备故障诊断"；不是"1500 个词元"，而是"1500 次生产排程优化" |
| 作用二：让词元**可比较** | 不同 Agent 的词元可以比较，通过语义锚点判断哪个更"重"、哪个更"值钱" | 设备监测 Agent 的 1000 个词元与质量 Agent 的 2000 个词元；查询设备状态的词元语义复杂度低、单位价值可能较低；执行设备故障诊断的词元语义复杂度高、单位价值可能较高 |
| 作用三：让词元**可定价** | 定价不再是拍脑袋，而是基于语义锚点；依据不是词元数量，而是**语义复杂度、服务等级、业务价值** | 查询设备状态的词元价格可以低一些；执行设备切换的词元价格可以高一些 |

注意原文对"可比较/可定价"用的是"**可能**较低/较高""可以低一些/高一些"，不是确定规则。

## 3 有效词元：语义定义与判定

### 3.1 定义

> 只有**同时满足时延、可用性、准确率等服务等级要求**、**最终被用户实际使用**的输出词元，才进入**商业计量**，这就是**有效词元**。（12.3.1 / PDF 第 209 页）

定义的三个关键词逐条展开（PDF 第 209 页）：

| 关键词 | 原文说明 | 原文举例 |
|--------|---------|---------|
| 服务等级要求 | 时延不能太长、可用性不能太低、准确率不能太差 | 如果一个 Agent 调用花了 10 分钟，时延严重超标，那么这 10 分钟内产生的词元不应该被全额计量 |
| 被用户实际使用 | 词元必须是最终被用户实际使用的 | Agent 生成 1000 个词元的输出，用户只看了前 100 个词元的结果，那么只有前 100 个词元应该被计量 |
| 进入商业计量 | 只有满足前两个条件的词元才进入商业计量，不满足的不进入 | — |

### 3.2 四项判定

原文指出"有效词元的判定，依赖本体的语义模型"（12.3.2 / PDF 第 209–210 页），随后给出四项判定：

| 判定 | 本体中定义了什么 | 原文示例 | 原文的业务化说明 |
|------|---------------|---------|----------------|
| 判定一：时延是否满足 SLA | 服务的时延约束 | 设备状态查询 SLA 是"**3 秒内返回**"，实际返回 5 秒 → 不满足 | 不是"越快越好"，而是按业务场景定义：设备故障告警要求**秒级**；设备健康评估要求**分钟级**。时延约束需业务专家参与、由本体记录 |
| 判定二：可用性是否达标 | 服务的可用性要求 | 质量检测服务可用性要求"**99.9%**"，实际 99.5% → 不达标 | 关键业务服务要求高（设备故障诊断服务不能宕机）；非关键业务相对较低（历史数据查询服务可以容忍短暂不可用） |
| 判定三：准确率是否达标 | 服务的准确率要求 | 缺陷检测准确率要求"**95% 以上**"，实际 90% → 不达标 | 质量检测要求高（漏检可能导致批量缺陷）；设备状态查询要求相对较低（误差可在后续环节修正） |
| 判定四：是否被用户实际使用 | 业务闭环 | 设备故障诊断 Agent 生成诊断报告 → 决策 Agent 使用 → 生成切换方案 → 执行 Agent 执行切换，构成完整业务闭环 | 若诊断报告只是被查看、没有被决策 Agent 使用，则诊断报告的词元不计入商业计量 |

原文强调："**业务闭环的定义，是有效词元判定的核心。**"

### 3.3 计算公式与参数（必看页 210–211）

必看页 210 为"**有效词元判定流程图**"，顶部注释重复定义："只有同时满足服务等级要求、被用户实际使用的输出词元，才进入商业计量。"流程图结构：左侧「总词元」→ 四个菱形判定节点依次串联——「时延是否满足 SLA？」「可用性是否达标？」「准确率是否达标？」「是否被用户实际使用？」——每个节点"是"走向下一节点，"**否**"则向下输出红框「**不计入商业计量**」；四个节点全部"是"之后进入绿框「**有效词元**」→ 「**商业计量**」。图左下"结构说明"：判定节点为菱形，不通过则输出"不计入商业计量"；通过为绿色、不通过为红色。

必看页 211 为"**有效词元的计算公式及案例**"图，把公式拆解成三段：左侧「总词元」、中「服务等级系数」、右「实际使用系数」。

**公式（原文，逐字保留）：**

> **有效词元 = 总词元 × 服务等级系数 × 实际使用系数**

**参数定义（原文）：**

| 参数 | 原文定义 | 取值规则 |
|------|---------|---------|
| 服务等级系数 | 取决于**时延、可用性、准确率**是否满足 SLA | 全部满足，系数为 **1**；部分满足，系数为 **0.5—1**；不满足，系数为 **0** |
| 实际使用系数 | 取决于词元是否**被用户实际使用** | 被使用，系数为 **1**；未被使用，系数为 **0** |

图示补充（页 210 图内小字）：总词元 = "输出的全部词元数量"；服务等级系数 = "SLA 达标的综合系数（0 ~ 1）"；实际使用系数 = "被用户实际使用的比例（0 ~ 1）"。

> 需要留意：正文参数定义只说实际使用系数"被使用=1、未被使用=0"（二值），而示例与图内小字又把它当作**比例**（0.8）。两种表述在原文中同时存在，原文未说明何时用二值、何时用比例。本页照录，不做调和。

### 3.4 原文算例（设备 Agent）

（12.3.3 / PDF 第 211 页，页 211 图重述）

- 设备 Agent 生成 **1000 个**词元；
- 时延满足 SLA、可用性达标、准确率达标 → 服务等级系数 **L = 1**；
- 用户实际使用了 **800 个**词元 → 实际使用系数 **U = 0.8**。

> **有效词元 = 1000 × 1 × 0.8 = 800 个词元**

原文结论："只有这 800 个有效词元进入商业计量。"

### 3.5 有效词元的三个意义

（12.3.4 / PDF 第 211 页）

| 意义 | 原文论证 |
|------|---------|
| 意义一：避免"**刷词元**" | 没有有效词元概念，Agent 可能通过生成大量无用词元来"刷词元"增加收入；有效词元要求必须满足服务等级、必须被用户实际使用，从而避免刷词元 |
| 意义二：**激励高质量服务** | 时延短的 Agent 获得更多有效词元，准确率高的获得更多，可用性强的获得更多 |
| 意义三：实现**公平交易** | 客户只为实际使用的、满足质量要求的词元付费；供应商通过高质量服务获得更多收入 |

## 4 词元经济的本体基础

12.4 节对四个环节分别列出"本体必须提供什么"，是本页最可操作的对照表（PDF 第 212–213 页）。

### 4.1 词元登记（12.4.1）

| 登记项 | 原文提出的问题/要求 | 本体提供什么 |
|-------|-------------------|-------------|
| 词元 ID | 需要唯一标识；标识编码应符合《**数据基础设施标识要求**》 | 词元 ID 关联到本体中的词元实体；词元实体有明确的类型、来源、权属、有效期 |
| 词元类型 | 数据访问词元、模型推理词元、工具调用词元、Agent 协同词元 | 每种词元类型关联到本体中的服务类型 |
| 词元来源 | 来自哪个 Agent？哪个模型？哪个工具？ | 关联到本体中的 Agent 实体、模型实体、工具实体 |
| 词元权属 | 归 Agent 提供方，还是平台运营方，还是数据提供方？ | 关联到本体中的机构实体、个人实体 |
| 词元有效期 | 什么时间段内有效？ | 关联到本体中的时间约束 |

### 4.2 词元计量（12.4.2）——三个基础

| 基础 | 本体提供什么 | 用于什么 |
|------|------------|---------|
| 基础一：**语义锚点** | 词元关联到实体、属性、关系、行动 | 精确识别词元代表的业务含义 |
| 基础二：**服务等级** | 时延、可用性、准确率要求 | 判定是否为有效词元 |

## 5 词元经济的运营模式

12.5 节给出"生产 → 消费 → 定价 → 交易 → 结算"五环节，外加一个运营主体（PDF 第 213–214 页）。

### 5.1 词元生产（12.5.1）

| 维度 | 原文内容 |
|------|---------|
| 生产者 | Agent 提供方、模型提供方、工具提供方、数据提供方 |
| 生产方式 | 词元通过 Agent 调用产生：调用数据→数据访问词元；调用模型→模型推理词元；调用工具→工具调用词元；Agent 协同→Agent 协同词元 |
| 生产计量 | 通过**词元运营中心**计量，每一次 Agent 调用都精确计量 |

### 5.2 词元消费（12.5.2）

| 维度 | 原文内容 |
|------|---------|
| 消费者 | 行业用户、智能体开发方、数据服务商、生态伙伴 |
| 消费方式 | 行业用户购买词元用于调用 Agent 服务；智能体开发方购买词元用于**训练和测试** Agent；数据服务商购买词元用于**数据产品开发和运营** |
| 消费计量 | 同样通过词元运营中心精确计量 |

### 5.3 词元定价（12.5.3）

定价方式："**成本加成 + 市场供需 + 质量分级 + 场景差异化**"综合定价模型。

| 因子 | 原文规则 |
|------|---------|
| 成本加成 | 词元价格 = 成本 + 合理利润；成本包括**算力成本、数据成本、模型成本、人力成本** |
| 市场供需 | 需求旺盛时价格上升，需求不足时价格下降 |
| 质量分级 | 质量高价格高，质量低价格低 |
| 场景差异化 | **高风险场景价格高，低风险场景价格低** |

### 5.4 词元交易（12.5.4）

| 维度 | 原文内容 |
|------|---------|
| 交易方式 | 直接购买、订阅服务、按需付费、收益分成 |
| 交易平台 | 通过词元运营中心进行；运营中心提供登记、计量、定价、交易、结算**全流程服务** |
| 交易规则 | 遵循**公平、公开、公正**原则；交易记录全程存证，支持审计追溯 |

### 5.5 词元结算（12.5.5）

| 维度 | 原文内容 |
|------|---------|
| 结算方式 | 自动结算、分账、清算 |
| 结算周期 | 实时结算、日结、周结、月结 |
| 结算记录 | 不可篡改，支持审计追溯 |
| 收益分配 | 按贡献分配：数据提供方、模型提供方、工具提供方、Agent 提供方、平台运营方**按约定比例**分配 |

### 5.6 DAC 词元运营中心（12.5.6 / PDF 第 214 页）

- **发起**：2026 年**全球数据资产大会**期间，**DAC 全球数据资产理事会**组织**高颂数科、华东数交**等多家机构联合发起"**词元运营中心**"。
- **定位**：实现词元登记、计量、定价、交易、结算全流程的运营平台；是"智能体经济的价值引擎，是数据资产价值计量的基础设施"。
- **边界**：原文明确"**不直接做词元交易，但为词元交易提供可信计量基础设施**"，让每一次 Agent 调用"可计量、可定价、可交易、可结算"。

## 6 词元经济与数据飞轮

### 6.1 词元经济是数据飞轮的"价值引擎"

（12.6.1 / PDF 第 215 页）

国家数据局提出的"数据飞轮"包括四个环节：**场景牵引数据 → 数据驱动模型 → 模型赋能应用 → 应用创造价值**。

原文断言："词元经济是'**应用创造价值**'环节的核心机制。"其论证是：应用创造价值，如何计量？如何定价？如何交易？如何结算？——通过词元计量、定价、交易、结算，应用创造的价值可以被**精确计量、合理定价、有效交易、公平分配**。结论句："没有词元经济，数据飞轮就无法完整闭环。"

### 6.2 本体是词元经济的"语义底座"

（12.6.2 / PDF 第 215 页）

| 环节 | 依赖的本体内容 |
|------|--------------|
| 词元登记需要本体 | 词元 ID、词元类型、词元来源、词元权属、词元有效期 |
| 词元计量需要本体 | 语义锚点、服务等级、业务闭环 |
| 词元定价需要本体 | 服务类型、服务复杂度、服务质量 |
| 词元交易与结算需要本体 | 交易主体、交易标的、交易规则 |

原文的一句话结论："本体是词元经济的'语义底座'。没有本体，词元就只是一个数字。"

### 6.3 高颂数科的词元经济前瞻（必看页 216–217）

#### 6.3.1 双轮驱动

（12.6.3 / PDF 第 216 页）

| | 本体定义世界 | 词元驱动未来 |
|---|---|---|
| 提供什么 | 一个**可理解、可推理、可行动**的业务世界 | 一个**可计量、可定价、可交易、可结算**的价值单元 |
| 定义内容 | 对象（设备、产线、工艺、订单、客户、供应商）；关系（设备属于产线、产线生产订单、订单交付客户）；行动规则（设备故障时必须停机、订单延迟时必须通知客户） | — |
| 效果 | 智能体"不再面对一堆孤立字段，而是面对一个可理解、可推理、可行动的业务世界" | 服务从"无法计量/定价/交易"走向"精确计量/合理定价/有效交易"；价值从"隐性→显性、模糊→精确、静态→流动" |

原文的"双轮"定义："本体与词元的协同，构成智能体经济的双轮驱动。**本体解决'是什么'的问题，词元解决'值多少'的问题。**"

两个反向命题（原文并列）：
- **没有本体，词元就只是一个数字**——1000 个词元可能代表一次设备数据查询，也可能代表一次设备数据分析，没有语义就没有意义。
- **没有词元，本体的价值就无法被计量**——本体定义了业务世界，但本体本身不产生价值，本体的价值体现在被智能体使用，每一次使用都产生词元。

#### 6.3.2 四步工程路径

## 8 本页分析（归纳，非原文）

> 以下为跨章串联，不属于原文叙述。

1. **"有效词元"是把"服务 SLA"下沉为"计量口径"**：传统 SLA 是合同概念（不达标赔钱），有效词元把它翻译成计量系数（不达标则部分或全部不计入）。这意味着本体的服务等级约束同时是**合同条款、计量规则、审计依据**——一条约束三处复用。与 [[trusted-ai-infrastructure]] 中 TAV 验证的"分级验证"思路同构。
2. **四层锚点是"词元粒度"的设计语言**：实体锚点定"谁"、属性锚点定"什么信息"、关系锚点定"与谁相关"、行动锚点定"能做什么"。词元若只锚到实体层，就只能按"查询/调用"计价；锚到行动层（带前置条件、参数、后置影响）才能支撑"按业务结果计价"。这解释了第 11 章为什么把"价值释放系数"与"业务闭环"绑定——行动锚点正是业务闭环的可判定接口。
3. **词元登记的五要素（ID/类型/来源/权属/有效期）几乎是"资产凭证"的字段清单**：把它和第 11 章《数据产权登记工作指引》的"权益属性四要素"（登记主体、数据权益、取得方式、承诺书）并置，可以看到同一套登记思想从"数据"延伸到"词元"。前者是 [[ontology-rights-and-data-asset-capitalization]] 的制度侧，后者是本页的技术侧。
4. **"不直接做词元交易"是一种基础设施定位选择**：与 [[data-asset-operation-2]] 中"运营方不自营交易、只提供连接与计量"的角色设定一致；在 [[small-world-network]] 的拓扑语言里，这是"枢纽节点提供度量而非内容"的模式——值不值得复用，取决于该枢纽自身的可信度。
